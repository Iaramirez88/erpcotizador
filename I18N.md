# i18n (ES/EN) — Guía rápida

Este proyecto usa un i18n **interno** (sin rutas `/en`) basado en:
- Diccionario plano de mensajes en `src/lib/i18n/messages.ts`
- Hook client `useI18n()` desde `src/components/providers/i18n-provider.tsx`
- Helper server `tServer()` en `src/lib/i18n/server.ts`
- Persistencia de idioma por usuario en `/api/ui-preferences` (si hay sesión)

## Cómo se determina el idioma

Orden de prioridad (client):
1) **Cookie** `sgd_language`
2) **localStorage** `sgd_language`
3) **Backend** `GET /api/ui-preferences` (si hay sesión)
4) `initialLanguage` (si el layout lo pasa) o `DEFAULT_LANGUAGE` (`es`)

Al cambiar idioma con `setLanguage(next)`:
- Se escribe cookie
- Se escribe localStorage
- Se intenta persistir en backend con `PUT /api/ui-preferences`

## Client Components (React)

Usa `useI18n()`:

```tsx
'use client'

import { useI18n } from '@/components/providers/i18n-provider'

export function Example() {
  const { t, language, setLanguage } = useI18n()

  return (
    <div>
      <h1>{t('quotes.page.title')}</h1>
      <button onClick={() => setLanguage(language === 'es' ? 'en' : 'es')}>
        {t('common.language')}
      </button>
    </div>
  )
}
```

Interpolación de variables:

```tsx
t('quotes.confirm.sendEmail', { numero: 'COT-123', email: 'a@b.com' })
```

Notas:
- Si usas `t()` dentro de `useMemo`, incluye `language` en las dependencias para recalcular al cambiar idioma.

## Server Components / Server Actions

Usa `tServer()` (es **async**):

```tsx
import { tServer } from '@/lib/i18n/server'

export default async function Page() {
  const title = await tServer('quotes.page.title')
  return <h1>{title}</h1>
}
```

Si ya conoces el idioma (por ejemplo, lo pasas desde un layout), puedes enviarlo como 3er parámetro:

```ts
await tServer('common.save', undefined, 'en')
```

## Agregar nuevas traducciones

1) Define una key en ambos idiomas dentro de `src/lib/i18n/messages.ts`.
   - El diccionario es **plano**: keys tipo `'quoteBuilder.page.title'`.
   - Mantén namespaces consistentes (ej. `auth.*`, `quotes.*`, `quoteBuilder.*`, `printshopQuote.*`).

2) Usa la key en UI con `t('namespace.key')`.

3) Si falta una key:
   - `translate()` hace fallback a ES si está disponible.
   - Si tampoco existe en ES, devuelve la key (se verá en UI), lo cual ayuda a detectar faltantes.

## Formateo locale-aware (moneda/fechas)

El i18n solo traduce textos. Para moneda/fechas, usa el `language` para derivar el locale:
- `es` → `es-CO`
- `en` → `en-US`

Ejemplo:

```ts
const locale = language === 'en' ? 'en-US' : 'es-CO'
const money = new Intl.NumberFormat(locale, { style: 'currency', currency: 'COP' }).format(123456)
```

## Convenciones recomendadas

- Prefiere frases completas sobre piezas sueltas cuando hay contexto (mejor consistencia de traducción).
- No reutilices una key con dos significados distintos.
- Mantén mensajes cortos (los textos largos mejor como plantillas específicas del módulo).
